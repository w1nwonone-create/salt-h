## 2. 예시 데이터에 대해

- 반출 제한 데이터는 센터 밖에서 원본을 확보할 수 없으므로, 같은 컬럼 구조의 예시 데이터로 Agent 전체 흐름을 검증합니다.
- 생성 방식: 장소별 도민·관광 소비 기반값 × 월별 관광 지수 × 요일·시간대 가중 × 강수 영향 + 잡음 (seed 고정, 결정적).
- **예시 데이터의 수치는 실제 상권 실적이 아니며, 리포트의 결론도 실제 상권에 대한 판단이 아닙니다.**
- Critic 의 동작을 확인할 수 있도록 일부 결측(외식업 포스 일부 월, 방문인구 일부 일, 관측소 강수 일부 일)과
  연도별 성장 차이(연도 효과)를 의도적으로 넣었습니다.
- `places.yaml` 의 법정동 코드는 예시 코드입니다. 실데이터 연결 시 행정표준코드 기준으로 교체합니다.

## 3. 전처리 흐름

1. **수집** — 반출 가능 데이터는 CSV 로 `data/raw/` 에 저장. 반출 제한 데이터는 센터 분석 환경에서 직접 불러와, 센터 PC 안에서 집계까지 수행한 뒤 가공 결과만 다룹니다. API Key 는 `.env` 로만 관리합니다.
2. **표준화** — 날짜(YYYY-MM-DD), 연월(YYYYMM), 지역 코드(격자 ID·법정동 코드·행정동명), 업종 코드를 공통 기준으로 통일합니다.
3. **공간 연결** — 정류소·관측소 좌표를 후보지와 거리로 연결하고, 후보지 좌표를 UTM-K 500m 격자로 변환합니다(`tools/geo.py`).
4. **파생 변수** — 성수기(7~8월)·비수기(11~2월), 주말·공휴일, 우천일(일강수량 1mm 이상)은 분석 코드 안에서 만듭니다. 서로 다른 시간 단위의 데이터는 억지로 결합하지 않습니다.
5. **품질 점검** — 결측·이상치는 표시만 하고 임의로 보정하지 않습니다. Critic 이 영향을 판단해 한계로 명시합니다.
6. **저장** — DuckDB 단일 파일(`jeju.duckdb`)로 저장해 센터 PC 에서도 빠르게 조회합니다.

## 4. 센터 실데이터로 바꾸는 방법

1. 센터 분석 환경에서 각 데이터를 위 테이블명·컬럼명으로 DuckDB 에 적재합니다(필요 시 컬럼명만 맞추는 뷰 생성).
2. `ref_holiday(holiday DATE)` 테이블을 함께 만듭니다(요일 평균 계산용).
3. `.env` 의 `JEJU_DB_PATH` 를 그 DuckDB 경로로 지정합니다.
4. `places.yaml` 의 법정동 코드·좌표를 실제 코드로, 필요하면 `tools/geo.py: grid_id()` 를 센터 격자 ID 체계로 맞춥니다.

## 5. 이용 조건 · 개인정보 보호

- 제주데이터허브·제주빅데이터센터 이용약관과 반출 정책을 준수하며, 리포트 하단에 출처를 자동 표기합니다.
- 활용 데이터는 모두 집계 단위(시간대·요일·격자·정류소)이며 개인을 식별할 수 있는 정보를 포함하지 않습니다.
- 반출 제한 데이터는 “분석·시각화 등 가공 형태로만 반출 가능” 조건에 따라 리포트에 가공된 집계 결과만 담습니다.
- 외부 LLM 에는 원본 데이터를 보내지 않고 질문·컬럼 구조·집계 결과만 전달합니다. 외부 전송이 허용되지 않는 환경에서는 오프라인 모드를 씁니다.
- 이용 건수 5건 미만 집계 셀, 외식업 표본 점포 3곳 미만은 리포트에 노출하지 않습니다.
